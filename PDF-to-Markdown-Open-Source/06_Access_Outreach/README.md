# Research Access Outreach

This folder tracks a **research-access outreach track** — separate from any
paid-collaboration/sponsorship outreach the wider AIDemos team may run.

**Purpose:** contact the maintainers/companies behind the open-source
PDF-to-Markdown tools included in `00_Project_Notes/Tool_Landscape.md`, to
ask whether there's a supported way to evaluate their tool properly
(hosted demo, evaluation credits, model access, a recommended CPU/GPU
setup, etc.) — not to pitch sponsorship, paid reviews, or featured
coverage.

## Scope

Only tools already marked **Tier A / Tier B / included** in
`Tool_Landscape.md` and `Decisions_and_Exclusions.md` are in scope.
Already-excluded tools (Tier C) and already-tested/covered tools from the
prior research cycles are explicitly out of scope for this outreach.

## Files

- `Contact_Research.md` — who's actually behind each tool, and the best
  verified contact route found (or "no verifiable contact — GitHub only").
- `Outreach_Tracker.md` — the master tracking table: tool, contact,
  access requested, date sent, status, response, access received.
- `Email_Templates.md` — the actual email copy used per tool/category.
- `Sent/` — copies of emails actually sent (date-stamped).
- `Responses/` — copies of any replies received.
- `Access_Received/` — record of what access was granted and what it lets
  us test. **Never store passwords, API keys, or other secrets here** —
  if credentials are received, this folder records only that access was
  received and that credentials are stored securely outside the
  repository.
- `Followups/` — follow-up notes/timing.

## Ground rules

- No fabricated contacts, partnerships, affiliations, or responses.
- No guessed email addresses.
- No secrets committed to git, ever.
- Every claim of "sent" or "access received" in these files corresponds to
  an actual action taken — not a draft, not a plan.
